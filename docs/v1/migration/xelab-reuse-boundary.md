# PsiOS 组件准入与实现边界

本文作为 PsiOS 工程治理检查清单，不定义额外的系统实现来源或软件发布范围。规范性约束以 PsiOS 的架构、API Schema、ADR 和实测验收为准。

## 一、核心实现原则

PsiOS Host Core、Task/Event、Broker、OCI、Identity/Policy、Storage、SDK、Agent 和 PsiOS Shell 均使用统一资源身份、权限、错误模型、生命周期与运维契约。每个模块应当有可追溯的源码提交、构建产物和接口测试。

## 二、组件准入检查

| 领域 | 必须核验 |
|---|---|
| 模块边界 | 输入输出 API、状态所有权、升级及兼容窗口 |
| 安全隔离 | 最小权限、宿主代理、身份映射、Secret、撤权与审计 |
| 依赖与许可证 | 版本锁定、许可证、供应链风险、可替换性 |
| 容器执行 | OCI 生命周期、只读根、挂载、设备限制、异常退出与恢复 |
| 数据持久化 | 原子提交、配额、满盘、备份恢复、权限及数据所有权 |
| 任务与事件 | 幂等、重试、结果未知、持久化、异常中断、重复投递 |
| 接口与 SDK | Schema、协议版本、错误码、客户端一致性 |
| GUI 与 Agent | 同一系统授权、输入租约、会话撤权及测试证据 |

## 三、证据与验收

每次准入评审记录准确的 PsiOS 提交 SHA、依赖锁定信息、构建摘要、环境、测试命令、失败注入点、日志、预期及实际结果、复核人和未通过项。文件名或制品摘要不等同于功能已经实现。

通过条件是接口与状态语义可验证、跨模块授权正确、失败时可以恢复或安全拒绝；无法保证时需保持 NotVerified / NotRun 并提供替代方案。

## 四、维护边界

可复用通用开源标准与经评估的第三方依赖，但项目架构、源代码事实、数据契约及发布资格只由 PsiOS 自己定义和验证。本清单不能替代 ADR-17 或具体模块的测试记录。
